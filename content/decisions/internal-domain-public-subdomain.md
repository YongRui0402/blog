家裡的自架服務原本用一個假的頂級網域(`.home` 之類),配自簽 CA。
乾淨、離線、不依賴外部 —— 帳面上都對。

實際用起來,每一台新裝置都要付三道稅。

## 原本的樣子

```
名稱   git.home / vault.home / photos.home …
解析   本地 DNS 伺服器的改寫規則
憑證   自簽 CA，手動簽發、手動部署
```

新裝置要能用,得做三件事:

1. **裝 CA 憑證** —— 每台電腦、每支手機。iOS 還要分兩步(安裝描述檔 + 到
   「憑證信任設定」裡手動啟用),而那第二步藏得很深
2. **手動指定 DNS** —— 因為 `.home` 只有家裡那台 DNS 認得
3. **改 VPN 設定檔** —— 在外面要能解析,得在 `.ovpn` 裡塞 `dhcp-option DNS`

三件事都不難,但**每一台裝置都要做一次**,而且做錯的症狀都是
「網頁打不開」或「憑證不受信任」,分不出是哪一步壞的。

真正讓我下定決心的是:家人的手機我不可能一台一台去弄,
所以他們只能背 IP 位址。

## 換成什麼

```
名稱   git.home.example.com / vault.home.example.com …
       （example.com 是我本來就有的公開網域）
解析   公開 DNS 一筆萬用 A 記錄 → 內網 IP（不代理）
       ＋ 本地 DNS 也有一份萬用改寫（斷網時的備援）
憑證   Let's Encrypt 萬用憑證，走 DNS-01，反向代理自動續期
```

三道稅同時歸零:

- **不用裝 CA** —— Let's Encrypt 是全球信任的
- **不用改 DNS** —— 名稱在公開 DNS 上,電信商的 DNS 就查得到
- **不用改 VPN 設定** —— 原廠設定檔直接可用,VPN 只負責把封包路由進內網

新裝置的設定成本從「三個步驟 + 一堆踩坑」變成**零**。

## 為什麼不是別的方案

### 為什麼不繼續用自簽 CA

自簽 CA 的成本被嚴重低估,因為它**不在建置的時候發生**。
建 CA 很快,簽憑證很快 —— 稅是在之後每一台裝置、每一次重灌、
每一個訪客上收的。

而且它有到期日。憑證兩年後要重簽,那時候你已經忘記當初怎麼做的了。

### 為什麼不用 `.local` 或 mDNS

`.local` 是 mDNS 的保留網域,和一般 DNS 混用會有各種平台差異。
而且一樣沒有可信任的憑證。

### 為什麼不把服務放到公網

不想。這些服務本來就只該在內網,開到公網等於多一個攻擊面,
還要處理認證、防爆破、更新節奏。**能不開就不開。**

### 為什麼不用 Tailscale / WireGuard 之類的 mesh VPN

會是很好的方案,而且能一併解決「在外面」的問題。
沒選它是因為當時已經有一套 VPN 在跑,而且它不解決「憑證」那一半 ——
名稱和憑證的問題還是要另外處理。

如果從零開始,mesh VPN + 公開子網域可能是更好的組合。

## 代價與風險

**這個做法把內網的服務名稱和 IP 放在公開 DNS 上。**

任何人查 `git.home.example.com` 都會拿到一個 RFC 1918 位址。
這洩漏了:我有哪些服務、內網用哪個網段。

我的判斷是可以接受,因為:

- 私有 IP 對外部的人沒有用 —— 他們連不到
- 服務清單本來就不是秘密(而且從憑證透明度日誌也查得到子網域)
- 換來的是每台裝置零設定

**但這不是所有人都該接受的取捨。** 如果你的威脅模型在意「不讓人知道
你跑了什麼」,這個方案不適合 —— 憑證透明度日誌會把所有簽發過的名稱公開。
(用萬用憑證可以只暴露 `*.home.example.com` 一筆,不逐一列出子網域,
但網段還是會從 A 記錄洩漏。)

## 兩個實作上的坑

### DNS rebinding 防護

「公開網域解析到私有 IP」是 DNS rebinding 攻擊的特徵,
有些 DNS 伺服器和路由器會**直接過濾掉這種回應**。

動手之前先建一筆測試記錄,從**每一種你會用的網路**各查一次:
家裡 WiFi、行動網路、公司網路。有一種被擋就要重新考慮。

### 一定要保留本地解析

公開 DNS 是主力,但**家裡對外斷線時它就查不到了** ——
那時候你所有服務的名稱一起消失,而服務本身明明還活著。

所以本地 DNS 也要留一份同樣的萬用改寫當備援。兩邊指向同一個 IP,
平常誰回答都一樣,斷網時本地那份接手。

> 這一條很容易漏,因為平常完全看不出差別。要驗證本地那份到底有沒有生效,
> 看 **TTL** —— 本地改寫通常是固定的小值且不倒數,轉發上游的則會倒數。

## 一年後回頭看會不會後悔

會讓這個決定失效的前提:

- **Let's Encrypt 不再簽發萬用憑證**,或 DNS-01 流程改變 → 得回頭想辦法
- **公開 DNS 開始普遍過濾私有 IP 回應** → 目前只有部分 resolver 這樣做
- **搬到 mesh VPN** → 那時候這套會顯得多餘,但拆掉不難

寫下來是為了以後不用重新推導一次:當初選這個,是因為**成本發生在
每一台裝置上,而不是發生在建置的時候**。任何新方案都要先過這一關。
